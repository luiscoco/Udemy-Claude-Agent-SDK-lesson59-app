01

Distinguish four execution paths

Agent SDK and Claude Code CLI supply a local agent runtime. A Client SDK calls the Messages API; your application dispatches tools. Managed Agents hosts the harness and retains session events server-side.

02

Create a Managed Agents lifecycle

Create a dedicated agent, cloud environment and session; open the event stream, send a user event and observe the native idle event after the reply. The model key stays on the server.

03

Compare ownership before benchmarks

Inspect who owns the loop, process, tools and state. Run the same small expense policy on two platforms, but do not infer general quality, latency or price rankings from one classroom sample.

04

Choose from workload constraints

Embedded callbacks and in-process tools favor operating the Agent SDK. Long asynchronous work may fit Managed Agents. Conflicting retention requirements need review before a platform choice; neither a label nor local hosting guarantees compliance.

05

Review historical SDK migration

Inspect an obsolete import as text, replace the package reference and review explicit prompts, settings, tools and permissions. The old package is never installed. A real modern SDK run checks the small regression task.

06

Map primitives and verify state

Port a small function into an actual tool() / MCP handler, observe a real hook and distinguish delegation from conversation handoff. Compare SDK session_id/resume with a remote retained Managed session. Working files need their own persistence plan.
